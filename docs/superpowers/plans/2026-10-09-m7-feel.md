# M7 — Feel: toasts, motion, Google sign-in

User feedback after a day on a real phone: "everything looks fine" — improve the toast (bottom position
covers the + button and last rows), then small details, animations, smoothness; add Google sign-in.

## 1. Toasts (both apps)
- Top "pill" under the status bar (web: top-centre), ink background in light / light in dark.
- Slides down with a spring, auto-dismisses, swipe up (mobile) / click ✕ (web) to dismiss.
- Icon per kind: success ✓, undo ↶, error !, info/sync ☁. Undo on the right with a 5 s countdown bar.
- Haptic on show (mobile; success/warning/error by kind). Identical repeats coalesce ("Saved ×2").
- Never covers the FAB, the tab bar, a sheet's Save button or the keyboard. Respects safe areas.
- Same public API (`useToast()` on mobile, `toast()` on web) so call sites don't change.

## 2. Motion and detail (mobile first, web parity)
Principles: 150–250 ms, spring for movement, ease-out for fades; motion explains state changes, never
decorates; one shared set of durations/easings; `Reduce motion` (OS setting) collapses everything to
fades/instant. Mobile uses react-native-reanimated 4 + gesture-handler + expo-haptics (already installed,
no native rebuild). Web uses CSS transitions / Web Animations — no new dependencies.

- Quick log: amount digits roll, chips spring on select, Save morphs to ✓, sheet tracks the finger.
- Lists: entering/exiting/layout animations; swipe actions follow the finger; long-press menu on rows.
- Numbers: balance counts to its new value; progress bars fill; tabular figures, no width jitter.
- Navigation: tab cross-fade, sliding active-tab pill, smooth collapsing headers.
- Feedback: consistent press states, haptics map (light tap / selection / success / warning).
- Loading: skeletons shaped like content; no layout shift.
- Hero card: press tilt/shine; amounts blur in/out on hide/show.
- Empty states: small illustration + one action.
- Accessibility: reduce motion, font scaling, 48dp targets.

## 3. Sign in with Google
- Supabase Google provider (web OAuth client id + secret).
- Android: native account picker via @react-native-google-signin/google-signin → `signInWithIdToken`
  (Android client ids for the debug/release signing SHA-1s; requires a new APK build).
- Web: `signInWithOAuth({ provider: 'google' })` → existing `/auth/callback`.
- Same email ⇒ same Supabase user (automatic identity linking). Email sign-in stays as the fallback.
