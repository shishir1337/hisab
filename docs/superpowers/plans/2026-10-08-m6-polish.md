# Hisab M6 — Polish & Beta Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** First-run onboarding, editable preferences (currency, number grouping, time zone, name), app lock and "hide amounts", an "Unsynced issues" screen, "Remove data from this device", and account deletion. After this the owner can install a beta APK.

**Architecture:**
- Preferences live in the synced `profiles` row. If the row isn't on the device yet, it is upserted locally with the server's id; the server row already exists, so the upload is an update.
- Account deletion is a Supabase Edge Function that verifies the caller's JWT and deletes the auth user; table rows cascade.

**Spec:** §7.3 Settings & Onboarding, §8 (app lock, hide amounts, account deletion, export), §9 (Unsynced issues)

## Global Constraints
- Android + web only.
- No service-role key in any client; it is only used inside the Edge Function.
- Account deletion requires typing `DELETE`. This is the only confirmation dialog in the app.
- App lock re-locks after 1 minute in the background.

## Review Focus
1. **Saving preferences before the first sync** (no profiles row locally) creates the row with id = user id and doesn't duplicate it. Tested in Task 1.
2. **Changing number grouping** updates every amount immediately. This is reactive through `useProfile`.
3. **The delete-account function** rejects a missing or invalid JWT, and can only delete the caller. Verified by deploying it and calling it with no token.
4. **App lock when biometrics aren't enrolled** falls back to the device PIN, or the setting is disabled with an explanation.
5. **Discarding an upload issue** removes only that local issue record; it never deletes user data.

### Task 1: db — profile upsert and issues
- `saveProfile(ex, userId, patch)`: upsert the profiles row, with validation.
- `Q.uploadIssues`, plus `discardIssue` and `clearIssues`.

### Task 2: mobile — Onboarding
Shown when the profile has no `onboarded_at` and there are no accounts:
1. Welcome
2. Currency (BDT preselected) and number grouping
3. Accounts with their current balances (several allowed)
4. Optional: a running loan and people who owe you (links to the existing forms)
5. Done (sets `onboarded_at`)

### Task 3: mobile + web — Preferences, hide amounts, app lock, issues, device data
- **Settings:** display name, currency, number grouping and time zone.
- **Hide amounts:** a global toggle, stored in the profile.
- **App lock:** `expo-local-authentication`.
- **Unsynced issues:** a list with Discard.
- **Sign out:** offers "Sign out" or "Sign out and remove data from this device".

### Task 4: Account deletion
- Edge Function `delete-account`, deployed through MCP.
- Settings → Delete account: type `DELETE`, then sign out and clear local data.

### Task 5: Docs and final verification
- README (beta install via EAS, PowerSync setup, OTP template).
- `turbo typecheck test`, the web build, the Android bundle, and the web smoke test.
